这看起来是那么简单：在自己的 VPS 上用一个控制面板搭建一个网站。这不就搞定了吗？确实，几周之内就搭好了。安装和升级 WordPress 主题和插件虽然麻烦，但也并非做不到。运行几年之后，许多 WordPress 网站如今已经堆满了页面、博客文章等等。现在已有新技术可以取代 WordPress，但许多人面对的似乎是一道很高的门槛。

本周，许多拥有网站的人突然被敲响了警钟。运行 PHP 程序的 PHP 服务器中存在一个漏洞。漏洞并不在程序本身（例如 WordPress），而在底层的 PHP 服务器中。所以，即使这些年来你一直认真地更新 WordPress、主题和插件，这周你还是中招了……你可能会想：装个补丁就完事了。可惜并非如此，如果你没有让 PHP 服务器保持最新，就必须先升级它，然后才能安装补丁。随后有些人又发现，PHP 服务器下面往往还有一个过时的 Linux 操作系统和/或一个过时的数据库管理系统。

我真不想去数这周有多少人慌忙搭建一台全新的服务器，并把他们的 WordPress CMS 连同内容一起迁移过去。结果不出所料，旧的 CMS 无法在新的技术栈上运行，因此也必须升级。糟糕……当你在各处同时修修补补时，一旦出了问题，你很可能再也找不到原因所在。在流了大量的血、汗和泪之后，许多人如今运行的是一个依然过时的平台的新版本。

过去一个月里，我全面拥抱了 AI，并发现 WordPress 网站以及运行在其上的 WooCommerce 和 Shopify 网店，对 AI 窥探者是多么门户大开。你只需让 AI 去调查并总结一个网站，AI 就会开始工作，完全合法地获取需要调查的信息。

> 我预计，在接下来的一段时间里，AI（以及 AI 背后的人）将会在旧系统中发现并利用更多的漏洞。你刚堵上一个漏洞，下一个漏洞很快就会被找到。你可以选择：要么继续守着过时的东西艰难度日，要么咬咬牙，转向现代技术——它们的脆弱性要小得多，管理起来也要容易得多。

我自己也中招了。直到昨晚，这个网站还运行在 WordPress 上。当我开始为 WordPress CMS 底层的技术打补丁时，我发现在引擎盖下的深处运行着相当多过时的开源组件，其中包括 MySQL、PHP 和 CentOS。

我当机立断，把我的 WordPress 网站的信息迁移到了一个基于 Anthropic Claude、Cloudflare、GitHub 和 Sveltia（一个基于 Git 的无头 CMS）的 AI 解决方案上。这次迁移的轻松和快速，实在令人惊叹。

我只是让 Claude 为我的旧网站制作一个 AI 克隆。Claude 让我先导出 WordPress 网站，并允许 GitHub 从我的旧网站拉取媒体文件。Claude 在过程中有时会主动做一些“改进”，我并不总是认同。在就我希望这个网站做什么进行了一番愉快的对话之后，Claude 做了相应的调整。之后要做的就是把 DNS 路由从 Plesk 切换到 Cloudflare，这一步我让它在夜里完成。今天早上，这个网站已经运行在 AI 上了……今晚我又加了一些安全和防护措施，配置了备份，让它生成了统计页面和管理页面，并启动了一个新的聊天机器人，还为它提供了训练内容。

2022 年，我花了整整一个圣诞假期，才把旧的 .NET 网站改造成 WordPress。如今，同样的事情——甚至更多——我两个晚上就完成了。我的网站以及自 2022 年以来我撰写的包含 60 篇文章的博客，一下子又变得滴水不漏，而且现在只使用现代组件。新网站是一个可以安全地开发和运行各种 AI 应用的平台。我原以为必须跨越的障碍，结果不过是一道低门槛。

**_我建议每一位使用或管理 IT 解决方案的人，都去掌握 AI，并加速告别过时的技术，最好赶在 AI 让这些旧技术瘫痪、或者某个不法之徒卷走数据之前。因为后者已经不是会不会发生的问题，而只是何时发生的问题。_**
